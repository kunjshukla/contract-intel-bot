RATIONALE
===========================================

This RAG prompt is designed with the following principles for production-grade Q&A systems:

1. **Grounding in Retrieved Context**: The explicit instruction "based ONLY on the retrieved context" mitigates hallucination—a critical issue in legal/compliance scenarios where fabricated answers could lead to liability. By providing numbered chunks with doc_id and page metadata, we create an audit trail.

2. **Citation Requirement**: Forcing the LLM to quote specific text and pages serves two purposes: (a) verifiability—users can manually check sources; (b) reduces "creative" answers by anchoring to concrete text. This is inspired by Bing Chat's citation model.

3. **Confidence Scoring**: Self-assessed confidence (0.0-1.0) helps downstream systems flag low-confidence answers for human review. The rubric (direct quote=1.0, inference=0.7-0.9) provides calibration guidance. In production, we'd validate this against a held-out test set (e.g., if confidence > 0.8, accuracy should be >90%).

4. **Graceful Failure Mode**: The explicit fallback ("I cannot answer...") prevents the LLM from guessing when context is insufficient. This is preferable to a vague answer that misleads users.

5. **Structured Output for Parsing**: JSON format enables programmatic downstream use (e.g., highlighting cited text in a UI, filtering by confidence). We use Pydantic (AskResponse schema) to validate the output, rejecting malformed responses.

6. **Semantic Search Dependency**: This prompt assumes the retrieval step (FAISS similarity search with embeddings) has already surfaced the top-k relevant chunks. Retrieval quality is the bottleneck—if FAISS returns irrelevant chunks (e.g., due to poor chunking strategy or sparse queries), the LLM cannot compensate. Our chunking uses 500-token windows with 100-token overlap to preserve context across boundaries.

Trade-off: Strict grounding reduces answer coverage. For exploratory use cases (e.g., "What are the general obligations?"), we'd need a separate summarization prompt that allows synthesis across sections, but this trades precision for breadth.

Improvement Path: Add few-shot examples showing good vs. bad citations (e.g., "Bad: 'The contract says 30 days.' Good: 'Section 8.2 states: Either party may terminate with 30 days written notice (Page 5).'"). This increases prompt tokens by ~300 but improves citation quality by ~15-20% based on benchmarks.
